Caveat: LADSPA control ports carry no enum nicks, so `filter-type` / `filter-mode` / `filter-slope` arrive as bare `gint` — the UI must hardcode the label↔index map from LSP docs, and it needs re-checking on any lsp-plugins version bump. **Dynamics: switch to the SELF-KEYED LSP elements** (`compressor-stereo`, `gate-stereo`, `expander-stereo`, `limiter-stereo`) instead of today's `sc-*` variants — a program compressor doesn't need a key, so this deletes the entire 4-channel `deinterleave`→`interleave` packing (program on 0/1, key on 2/3) and the `channel-mask=(bitmask)0x0` workaround. Keep `sc-gate-stereo` only for `gateKey=sidechain`, and keep ducking on the existing native `level`→`volume` control loop (exact floor, zero added latency, no LADSPA). Adds a **limiter** mode, which the module lacks today. **Deps unchanged** — `lsp-plugins-ladspa` + gst-plugins-bad `ladspa` PACKAGECONFIG are already required by audio-dynamics; resolve via `findLadspaElement('para-equalizer-x16-stereo')`. **Zero-dependency fallback** if LSP is ever dropped from the image: native `equalizer-nbands num-bands=6` is a genuine parametric EQ (`band0::type` = 0 peak / 1 low-shelf / 2 high-shelf, plus `freq` / `bandwidth` / `gain`; child-proxy `band0::` syntax verified working inline in a pipeline string) but is capped at −24…+12 dB and offers no HPF/LPF/notch band types. Writing our own C or Rust element (unified dynamics + EQ, native two-pad sidechain via `GstAudioAggregator`, no LADSPA at all) was costed at roughly 4–6 weeks and is deferred — revisit if the version-suffixed LADSPA element names ever break a fleet upgrade.
