Separate modules for encoding, muxing, decoding and demuxing?

Muiltiplexer to send multiple streams over single srt / rist, and demultiplex on receiving side, with options on how to split the stream into new multiplexed streams (e.g. sending 1 video stream and multiple audio streams, and mapping it to multiple video streams each with their dedicated audio channel)

Tailwind CSS V4 (avoid single styles file used in V1) 

Dgram comms / socker.io / webrtc data channel? 

Engine to manager comms: UDP (dgram) based with multi-path (send over multiple routes for redundancy, accept first receipt on receiving side and discard copies. Need to use numbering or unique identification scheme to know which packets belong together) 

Manager to web-ui comms: Socket.io / webrtc data channel? Which is more efficient / easy to implement? 

Engine to local control panel comms: Local control panel is web-based, and currently uses Socket.io for comms. As this is mostly just used locally on the devices, or in exceptional cases from a device on the local network, sticking to Socket.io might be ok? 

Nest.js for manager?? Or just one data endpoint where everything runs through like modular ui?  

We know Javascript / Typescript well, and prefer staying there, but if there are very good reasons to move to e.g. Go for the engine / manager, try to convince us.
